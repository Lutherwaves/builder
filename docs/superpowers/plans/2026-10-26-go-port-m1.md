# Go port, milestone 1: the `builder` binary beside the Python

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Go binary, `builder`, does everything the Python does today, behind a committed shim, and a parity test proves it gives the same answers on the same inputs.

**Architecture:** `cmd/builder` dispatches subcommands to `internal/*` packages, one per Python module. The binary reads the plugin's files (catalog, soul, harness mappings, reach defaults) from `BUILDER_ROOT`, which the shim `bin/builder` sets. The Python stays in place and stays the code that runs; milestone 2 switches callers to the shim and deletes the Python.

**Tech Stack:** Go (the `go` line of matchblox's `go.mod`: `1.26.10`), standard library, `github.com/BurntSushi/toml v1.6.0` (the version matchblox uses). Bash for the shim and the parity test.

**Spec:** `docs/superpowers/specs/2026-10-25-go-port-and-cleanup-design.md` (sections "Go port (project 2)", "Tests and CI", "Milestones"). This plan is milestone 1 only. Milestones 2 and 3 get their own plans after this one merges into `feat/go`.

## Global Constraints

- Branch: work on `feat/go`'s child branch `feat/go-m1`; the PR targets `feat/go`, never `main`.
- Module path `github.com/Lutherwaves/builder`. Layout exactly as the spec: `cmd/builder/`, `cmd/support-table/`, `internal/{harness,ledger,signals,reach,security,budget,hook,mcpmerge}/`, `bin/builder`.
- Standard library only, plus `github.com/BurntSushi/toml v1.6.0`.
- "Output text and exit codes stay byte-identical where a skill or test reads them." JSON output is compared parsed (key order and float spelling such as `0.0` vs `0` may differ); plain text output is byte-exact.
- On-disk formats do not change: `ledger.json`, `reach.json`, `reach-log.jsonl`, `security/<key>.json`, `tests/evals/results/<harness>.json`. A file the Python wrote, Go reads, and the reverse.
- `BUILDER_HOME` defaults to `~/.config/builder`, as today.
- The hook path makes no network call and finishes in under one second.
- Nothing in this milestone changes a skill, the hook script, the opencode plugin or a doc a person reads. Python callers stay as they are.
- Signed Conventional Commits, never `--no-verify`. Scope by package: `feat(ledger): …`, `test(parity): …`.
- Every `.go` file is `gofmt`-clean and `go vet`-clean.

## Review Focus

1. **Flags after positionals.** `builder security baseline save f.json --today 2026-10-01` must work, as argparse allows; Go's `flag` stops at the first positional. Task 1's `cli.Parse` test pins it.
2. **Non-UTF-8 bytes** in `ps` output, `config.toml` and JSON configs. Python reads with `errors="replace"` and never crashes; Go must not drop the whole signal either. Task 4 ports `test_non_utf8_*` and adds a Go case for invalid UTF-8 in `config.toml`.
3. **Cross-writer files.** A `ledger.json` with float `at` from Python loads in Go; a Go-written ledger loads in Python. Task 11's parity test runs `ledger answer` in Go, then `ledger.py next` in Python on the same home, and the reverse.
4. **Local time in the forecast.** `budget` multipliers use local hour and weekday; Go's `Weekday` numbers Sunday 0, Python's Monday 0. Task 8 runs its cases under `TZ=UTC` and `TZ=America/Los_Angeles` against fixed outputs from the Python.
5. **The shim under odd paths.** A plugin root and a `BUILDER_HOME` with spaces, and a `plugin.json` whose `"version"` line has extra spaces. Task 10's shim test covers both.
