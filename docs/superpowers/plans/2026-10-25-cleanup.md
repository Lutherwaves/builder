# Cleanup Implementation Plan (project 1 of 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A newcomer reads the README and knows in thirty seconds why builder and not superpowers, gstack or a plain `CLAUDE.md`. The team-channel nag is gone, questions follow one format, and the TUI leftovers are archived.

**Architecture:** Docs, one catalog edit, one skill section, and one new validate check. No runtime code changes.

**Tech Stack:** Markdown, Bash (`scripts/validate.sh`), Python unittest (still present until project 2).

**Spec:** `docs/superpowers/specs/2026-10-25-go-port-and-cleanup-design.md` (sections "Goals → Project 1", "Question format", "README outline").

## Global Constraints

- Base: `chore/repo-cleanup` is rebased onto `feat/brief-bluf`. The report format is brief-bluf's: ✓ Done / ▶ Needs you / ✗ Blocked, ▶ You, ⚠ Not proven, ✓ Proven, ↗ Outside, Calls, ↻ Next.
- README prose: plain English in paragraphs. Skills keep ASD-STE100.
- "Not proven" is a report field. The hedge check must not ban it.
- Each commit is a signed Conventional Commit. Never `--no-verify`.
- Public repo: grep the staged diff for private names before each commit.
- Any push, PR, tag push or branch delete waits for the owner's yes in this session.

## Review Focus

1. **A fresh ledger after the change.** Someone who never answered `channel` must not see it during or after onboarding. Task 1 asserts this on the real catalog, both before and after onboarding.
2. **An old ledger that holds `channel: later`.** It must not crash or show the step. `load()` keeps unknown ids, and `next_recommendation` only looks at catalog ids. Task 1 adds that test.
3. **"Not proven" in the README.** The hedge check must pass on brief-bluf's own report example. Task 3 runs it on a fixture that contains "⚠ Not proven".
4. **The validate run on a clean tree.** Every new check passes on the final tree. Task 5 runs the full `scripts/validate.sh`.
5. **A link in the README that points at a moved section.** Task 4 greps that every relative link target exists.
