# Go port, milestone 2: every caller on the shim, the Python gone

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The hook, the opencode plugin, every skill, the eval runner and the scripts call `bin/builder`; no Python file and no `python3` call remains outside the eval fixtures; `scripts/validate.sh` proves it.

**Architecture:** Milestone 1 put the `builder` binary and the shim `bin/builder` beside the Python, with a parity test. This milestone moves each caller to `"<plugin root>/bin/builder" <command>`, ports the last Python (the template test, the eval-config block of `parity.sh`, the inline heredocs) to Go, `jq` or Bash, and then deletes the Python and the parity test. When the binary is missing, the hook still prints the soul and no error; the install offer is milestone 3.

**Tech Stack:** Go `1.26.10` (from `go.mod`), standard library plus `github.com/BurntSushi/toml v1.6.0`; Bash; `jq`; Node for the opencode adapter test.

**Spec:** `docs/superpowers/specs/2026-10-25-go-port-and-cleanup-design.md` ("Go port (project 2)", "The hook without the binary", "Tests and CI", "Milestones" item 2). Milestone 1 plan: `docs/superpowers/plans/2026-10-26-go-port-m1.md`.

## Global Constraints

- **Branch.** Milestone 1 merged into `main` (#27), not into `feat/go`; that was safe because the Python still ran. Milestone 2 is not safe on `main`: a git install runs main HEAD, and no release has the binary yet. So this milestone works on `feat/go-m2`, branched from `feat/go`, and its PR targets `feat/go`, never `main`. Task 1 brings `feat/go` up to `origin/main` first.
- Every caller runs `"${CLAUDE_PLUGIN_ROOT}/bin/builder" <command>` (skills, with the quotes) or `"$PLUGIN_ROOT/bin/builder"` (scripts). Never a bare `builder`, never the binary path under `BUILDER_HOME`.
- A command's output text and exit codes do not change. Skill behaviour does not change: this is a port.
- On-disk formats do not change (`ledger.json`, `reach.json`, `reach-log.jsonl`, `security/<key>.json`, `tests/evals/results/<harness>.json`).
- The hook makes no network call, finishes in under one second, and never shows an error when the binary is missing.
- "No `python3` remains" means: no tracked `*.py` file and no `python3` word outside `tests/evals/<fixture>/` (the sample projects, their `allow`, `prompt` and `expect` files), `docs/superpowers/` and `CHANGELOG.md`.
- Skills keep ASD-STE100, 60 to 150 lines, and their `## Common mistakes` and `## Self-check` sections.
- Tests get the binary from `BUILDER_BIN` when set, else build it once into their temp dir with `(cd "$root" && go build -o "$tmp/builder" ./cmd/builder)` and export `BUILDER_BIN`.
- Never edit `CHANGELOG.md` or a manifest `version`. Signed Conventional Commits, never `--no-verify`. Grep the staged diff for private names before each commit.

## Not in this milestone

- The install offer in the hook, `install.answer`, `scripts/install.sh`, the publish workflow, the README install section, and a skill's "binary missing: stop and offer the install" line. All are milestone 3.
- The milestone 1 deferred minors (PR #27), except mcp-merge key order and number precision: Task 3 fixes that one, because `setup.sh` starts to use mcp-merge here.

## Review Focus

1. **A broken `PATH` at session start.** A hook can start with `PATH` empty or wrong. The shim today needs `env`, `dirname`, `sed` and `head`, so it fails, and the session gets only the soul. Expected: the full hook text. Task 2 makes the shim builtins-only; Task 4 calls it through `"$BASH"` and tests `PATH=/nonexistent`.
2. **No binary at all.** First session after the plugin update, before milestone 3's installer exists. Expected: the hook exits 0 with the soul, valid JSON for its harness, nothing on stderr, under 1 s; opencode falls back to the soul. Task 4 tests each shape.
3. **A person's `.mcp.json` merged without `jq`.** `mcpmerge.Merge` decodes into a `map`, so it sorts keys and turns `12345678901234567890` into a float. Expected: key order and numbers stay as written. Task 3.
4. **An existing budget watcher.** People who scheduled the watcher have a job whose prompt runs `burn-proj.py`, which this milestone deletes. The skill's duplicate check looks for the new command only, so it adds a second watcher next to a broken one. Expected: the skill finds the old job and offers to replace it. Task 6 pins the wording in the Go template test.
5. **A plugin root with a space.** Claude Code and Cursor can install under paths with spaces. Expected: every skill command quotes the shim path. Task 9 adds a validate guard; Task 4 runs the hook from a root with a space.
