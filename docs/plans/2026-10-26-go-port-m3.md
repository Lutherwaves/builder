# Go port, milestone 3: the binary installs itself, and a merge to main releases it

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A person with no binary gets one install offer in the session, says yes, and `scripts/install.sh` installs the checked binary of the plugin's version. A merge to `main` that CI passed releases the four binaries and bumps the plugin version, with no release PR to merge.

**Architecture:** The shim (`bin/builder`) already exits 3 and names `scripts/install.sh` when the binary is missing. This milestone ships that installer. It makes the Bash fallback of `hooks/session-start` turn exit 3 into the install offer, with the answer in `$BUILDER_HOME/install.answer`. It adds one line to each skill that calls the shim. It replaces release-please with matchblox's `release.yml` and `publish.yml`. Everything that runs without the binary is Bash 3.2 safe, and a macOS CI job proves it.

**Tech Stack:** Bash (3.2 and up), `curl`, `sha256sum` or `shasum`, optional `gh`; GitHub Actions; `go-semantic-release/action`; Go `1.26.10` from `go.mod` for the binary itself.

**Spec:** `docs/superpowers/specs/2026-10-25-go-port-and-cleanup-design.md` ("The shim and version pinning", "The installer", "The hook without the binary", "Release", "Milestones" item 3). Earlier plans: `docs/superpowers/plans/2026-10-26-go-port-m1.md`, `docs/superpowers/plans/2026-10-26-go-port-m2.md`.

## Global Constraints

- **Branch.** Work on `feat/go-m3`, branched from `origin/feat/go` (`d07db42`, milestone 2 merged as #29). The PR targets `feat/go`, never `main`. `feat/go` merges to `main` once, after this milestone, and that merge is released as builder 3.
- The shim's missing-binary line stays exactly `builder <version> is not installed. Install it: bash "<root>/scripts/install.sh"` (exit 3). The installer ships at that path.
- The hook makes no network call, finishes in under one second, and never shows an error when the binary is missing. It runs with a broken `PATH`: only Bash builtins, plus `/bin/date` behind a fallback.

## Review Focus

1. **The installer prunes a version another harness still runs.** `BUILDER_HOME` is shared, and harnesses can hold different plugin versions. An explicit `--version` of an older release must survive its own prune. Expected: the installed version always stays, plus the newest others up to three in total. Task 2 tests it.
2. **A failed check leaves a half-installed file.** Expected: a checksum, provenance or version mismatch leaves no `builder-<v>` and no temp file in `$BUILDER_HOME/bin`, and says "Nothing was installed." Task 2 tests each refusal.
3. **macOS Bash 3.2 and BSD tools.** CI is Linux only. Expected: the shim, the offer and the installer pass their tests under `/bin/bash` 3.2 with `shasum` and no `sha256sum`. Task 1 runs them in the `bash:3.2` container. Task 5 adds a `macos-latest` job.
4. **A corrupt `install.answer`.** Empty, one word, a non-number time, or a time in the future. Expected: the hook makes the offer again and never fails. Task 3 tests each case.
5. **The first release computes the wrong version.** The old tags are `builder-vX.Y.Z`, and go-semantic-release reads only `vX.Y.Z`. With no `v` tag it starts at `0.1.0`, below the plugin's `2.1.0`. Expected: the release refuses and says to push `v2.1.0`. Task 5's `check-next-version.sh` does it; `RELEASING.md` names the seed tag.

### Task 2: `scripts/install.sh` installs the checked binary

**Files:** Create `scripts/install.sh` (mode 0755), `tests/test_install.sh`.

**Interfaces:**
- `scripts/install.sh [--version vX.Y.Z|X.Y.Z] [-h|--help]`. The default version is the plugin's, read from `.claude-plugin/plugin.json` with the shim's regex. A version that does not match `^[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$` after the `v` is stripped → exit 2, `builder: "<x>" is not a version like 3.0.0`.
- Target: `uname -s` `Linux`→`linux`, `Darwin`→`darwin`; `uname -m` `x86_64|amd64`→`amd64`, `arm64|aarch64`→`arm64`. Else exit 1, `builder: no binary for <uname -s>/<uname -m>. builder ships for Linux and macOS on amd64 and arm64.`
- Source: `${BUILDER_RELEASE_URL:-https://github.com/Lutherwaves/builder/releases/download}/v<ver>/builder-<os>-<arch>` and `….sha256`, fetched with `curl -fsSL --proto '=https,file'`. A failed fetch → exit 1, `builder: cannot download <url>. Check the network and the version, then run again.` No `curl` → exit 1, `builder: curl is required. Install it, then run again.`
- Checks, in order, on a temp file in `$BUILDER_HOME/bin` (removed on any exit):
  1. Checksum. Use `sha256sum`, else `shasum -a 256`. Compare the first field with the first field of the `.sha256` file. A mismatch → exit 1, `builder: checksum mismatch for builder-<os>-<arch> v<ver>: expected <a>, got <b>. Nothing was installed.`
  2. Provenance, when `gh auth status` succeeds: `gh attestation verify <tmp> --repo Lutherwaves/builder --signer-workflow Lutherwaves/builder/.github/workflows/publish.yml --source-ref refs/tags/v<ver>`. A failure → exit 1, gh's output, then `builder: the provenance check failed for builder-<os>-<arch> v<ver>. Nothing was installed.`
  3. The binary runs: `<tmp> version` prints `v<ver>`. Else exit 1, `builder: the downloaded binary says "<got>", not v<ver>. Nothing was installed.`
- Install: `chmod 0755`, `mv -f` to `$BUILDER_HOME/bin/builder-<ver>`. Then prune. Among the files named `builder-N.N.N` (digits only), keep `<ver>` and the newest others until three remain. Delete the rest. Sort with `sort -t. -k1,1n -k2,2n -k3,3n` on the version part. Never touch other names. Then write `yes <epoch>` to `$BUILDER_HOME/install.answer`.
- Output: exactly one stdout line. `installed builder <ver> at <path> (checksum ok, provenance ok)`, or without `gh`: `installed builder <ver> at <path> (checksum ok, provenance not checked: gh is missing or signed out. Check it: gh attestation verify "<path>" --repo Lutherwaves/builder)`.

It builds a fake release under `$tmp/rel/v<ver>/` with fake binaries (`#!/bin/bash` + `echo v<ver>`) and their `.sha256` lines from `sha256sum` or `shasum -a 256`. It sets `BUILDER_RELEASE_URL=file://$tmp/rel`. A fake `uname` and a fake `gh` on a `PATH` dir set the target and the gh result. Cases:

  builder install: the helper binary is missing.
  Answer the person's request first. At the end of that reply, ask this once, word for word:

  On not now, run: "<root>/bin/builder" install-answer later
  On never, run: "<root>/bin/builder" install-answer never
  ```

  ```
  builder install: the helper binary of this plugin version is missing, and the person said yes to it before.
